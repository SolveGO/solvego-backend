# Redis Cache Performance Comparison

## 1. Experiment Overview

문제 목록 조회 API에 Redis 캐시를 적용하지 않은 경우와 Warm Cache 상태에서 적용한 경우를 비교하였다.

| 항목 | 설정 |
|---|---|
| Target API | `GET /api/problems?page=0&size=20` |
| Duration | 30 seconds |
| Repetitions | 각 조건 3회 |
| Cache OFF | Spring Cache disabled |
| Cache ON | Redis warm cache |
| VUs | 20, 50, 100, 200, 500, 1000 |
| Performance threshold | p95 < 500 ms |

## 6. Summary

- Cache OFF는 평균 p95 기준 최대 `20 VU`까지 500 ms 미만을 유지하였다.
- Cache ON은 평균 p95 기준 최대 `200 VU`까지 500 ms 미만을 유지하였다.
- Cache OFF 최대 평균 처리량은 `1000 VU`에서 `131.08 req/s`였다.
- Cache ON 최대 평균 처리량은 `200 VU`에서 `936.24 req/s`였다.
- k6 threshold 미달은 성능 목표 미달을 의미하며, 해당 결과도 JSON으로 저장하여 분석에 포함하였다.
- Redis 캐시는 데이터베이스 조회 부하를 줄여 응답시간과 처리량을 개선하지만, 높은 VU 구간에서는 다른 시스템 자원의 병목으로 응답시간이 다시 증가할 수 있다.
